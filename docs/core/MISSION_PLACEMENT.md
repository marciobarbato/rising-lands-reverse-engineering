# Physical mission placement and raw predicates

Stage 12, 2026-10-28, base `9e0efeaa8032cbef76f58236ebe2d34fff9501ae`. This contract was inventoried before implementation. Intact executable SHA-256 `6c556520c084b9300d9ac01900d1505126085c5f64b1ac5e5b615ea41c8543fb`; ranges are end exclusive.

APIs are `consultas_unidades.existe_unidade(mundo, indice)` for `ExisteEngin` `0x441fff..0x442025`, `consultas_unidades.visibilidade_unidade(mundo, indice)` for `EnginVisible` `0x4465bf..0x4465df`, and `colocacao_missao.colocar_unidade_missao(mundo, indice)` for `PlaceEngin` `0x456fa6..0x457058` plus shared epilogue `0x440d58..0x440d5e`. Matching world methods are exposed. These are lower primitives; missions retains the scan, predicate order and whole loader/orchestration.

Both queries truncate AX index to u16, then protect 0–799 in the writable 800×276-byte pool. `existe_unidade` returns the original EAX boolean `state +2 != 0`, including state 4. `visibilidade_unidade` returns the consumed raw AL byte at +72, without boolean normalization or a state/type/owner guard. It does not promise the address-containing upper EAX. Both preserve all memory. The predicates differ from `MundoUnidades.viva` and terrain discovery. Missions' original caller tests existence, then the raw +72 byte, before invoking placement; that wrapper is not reconstructed by core.

Placement reads the already prepared current u16 cell +8. It does not test activity, +72, selection, life or special flags. It calls existing `ocupar(indice,current,True)` (`SetEnginCollision` 0x442cb4), stores +72=1, reloads current cell, then for owners other than 4/200 calls existing discovery with BB+F5+2 and illumination with the reloaded BB+F5 sum and owner. All owners call minimap mode 4 with the live owner. Existing discovery includes its original extra one-cell margin. No previous occupancy is removed. Position, step, destination, state, route/search, animation/experience and sound fields remain unchanged, apart from collision's existing region-backup writes and +72.

The physical insertion tail is shared with production `SetSortEngin` through `insercao_unidades._aplicar_insercao`. Production retains its own preceding position/order/search stores. Original `PlaceEngin` calls only the tail. Fresh regressions compare both entries against original instructions and full world buffers. Dependency classes retain distinct caller checkpoints: mission 0x457019, production 0x446146; both target 0x476851 and preserve prior effects.

Supported physical domain matches the existing insertion provider: known unit types 0–25, owners 0–3/4/200, local camera 0–3, current cell within world dimensions 1–256, minimap 128×128 and normal-owner vision sum BB+F5 in 0–8. Larger vision stops before native discovery at caller checkpoint 0x457019→0x476851, retaining prior collision and +72. Invalid protected model inputs fail before effects. The query domain itself does not require these physical fields or type bounds. Neither constructor zeros nor placement establish mission-load readiness or complete remapping.
