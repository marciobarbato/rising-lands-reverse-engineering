# Unit volume and bounded sound request

Stage 10 inventory before implementation, 2026-10-28, on committed main `fe85cadcb07edcffbea365988aeacfc44f7a52c0`. Intact executable SHA-256 is `6c556520c084b9300d9ac01900d1505126085c5f64b1ac5e5b615ea41c8543fb`. Ranges are end exclusive.

Original bodies are `EnginEstSelectionne` `0x472174..0x4721a8`, `EnginGetVolume` `0x440c5d..0x440d5e`, `EnginAsk` `0x440d5e..0x440df0`, and production's conditional request `0x420f9e..0x420fb7`. `PlaySnd_PostSound` `0x48aa79..0x48aac0` calls `HandlSnd_Insert` `0x48a218..0x48a438`: that subsystem has handle allocation/replacement/resource effects, so it remains an explicit dependency. The new stage will not silently drop a requested sound.

Public read-only APIs: `selecao_unidades.unidade_selecionada(mundo, jogador, indice)` consumes AL owner/u8 and DX unit/u16 and returns the consumed AL boolean: nonzero unit +bd AND exact unit owner equality. It does not read the selection lists, activity, life or type. `voz_unidades.consultar_volume_unidade(mundo, indice, janela)` reads current cell +8, four u16 viewport words `(x,y,width,height)` corresponding to `0x508720..0x508728`, and local camera owner +selection flag. It reuses established `movimento.distancia_quadratica`: viewport center coordinates wrap to u16 before distance, and the u32 result is compared as signed i32. Squared distance <=145 selects 256, <=300 selects 180, <600 selects 100, otherwise 0. Unselected units halve that value with integer division. Volume is full EAX, including 256; it is not an AL return. Viewport words are explicit loaded inputs, with no invented camera default.

Supported unit pool is the live writable 800×276-byte bytearray; index truncates to u16 then requires 0–799. Selection owner truncates to u8; all owner/type/activity bytes are otherwise retained, including unknown types on these query paths. Camera owner requires 0–3. Malformed viewport/pool/index inputs are protected, separately from native unchecked behavior.

Public `solicitar_voz_unidade(mundo, indice, modo, flag, *, janela=None)` consumes unit AX/u16, mode DX/u16 and flag BL/u8. Hidden current cell for the local camera returns without writes or a volume query. Visible cell queries volume first, even for mode 16 or an active sound handle. Missing viewport data stops at original volume call `0x440d9f`→`0x440c5d`, retaining earlier state. Mode16 overrides volume to 256 only after that query. It then reads u32 handle +104, stores flag at +f9, and returns if handle differs from FFFFFFFF. Otherwise it raises an explicit dependency before the original call `0x440de7`→`0x48aa79`, with a portable request descriptor: opcode 0x50, code `(live_type<<16)|(mode<<8)`, flag/u8, volume/u32 and the relative live handle offset. The OR overlap for high mode bits is preserved. No handle or backend state is fabricated. The descriptor is evidence of a pending call, not a completed queue insertion or playback.

Public `retomar_solicitacao_saida` consumes placement's `0x420f9e` handoff. It compares the live building owner +4 to the local camera; different owner reaches economy's `0x420fb7` cleanup boundary directly. Equal owner calls the bounded request helper with mode 6/flag 0, then reaches that boundary only if the actual supported helper completes. A pending volume/sound dependency retains all prior placement/movement/flag effects. The continuation does not rerun those earlier stages. It is one-shot, with protected building 0–999 and preserved u16 metadata. Complete audio, production cleanup and actual mission operation remain separate.
