# Remapping allocation and temporary classification

Stage 15 inventory before implementation, 2026-10-28. This follows the integrated pre-allocation reset in [MAP_REMAP.md](MAP_REMAP.md). Original oracle SHA-256 remains `6c556520c084b9300d9ac01900d1505126085c5f64b1ac5e5b615ea41c8543fb`. The caller continuation is 0x42eebd through classification and the initial component-scan checkpoint 0x42ef8b; first-lock failure takes the original epilogue at 0x42f1d7. Natural obstacle query is 0x4752b8..0x475302.

Planned API `retomar_classificacao_remapeamento(mundo,pedido,*,alocar=None,fixar=None)` consumes the exact `RemapeamentoPendente` without repeating its clears. It calls `alocar(0,65536)`, truncates the returned handle to u32, then calls `fixar(handle)` even when handle is zero. Missing callbacks remain explicit dependencies at their original call sites. The lock callback supplies a live mutable 65,536-byte allocation or None for a null result. A null lock returns False immediately, preserving earlier reset/allocation effects and without inventing cleanup. Real Windows allocation/locking behavior remains external.

On a supported non-null result, the continuation first copies attribute bit 0 for all 65,536 cells in ascending order, then scans all cells again. It reuses the existing `regioes_mapa.obstaculo_natural` predicate against live u16 tiles, object bytes and the explicit 702-byte marker table; cells without a natural obstacle are changed to class zero. This two-pass order is retained rather than collapsed into one comprehension. Success returns a new explicit handoff retaining the live class buffer/handle before component allocation. It does not label regions, insert units, correct map edges, release resources or return final remap success.

Protected model validation must distinguish the null-lock path, which reads no terrain inputs, from the successful path, which requires exact-size writable class/attribute/object allocations, u16 tile values and explicit marker bytes. Invalid model allocations must be rejected before classification writes; callback side effects already completed remain visible. The temporary buffer may not alias the terrain inputs. No raw ETA table or synthetic zero marker default is treated as loaded runtime data.

Fresh native comparisons will bind only the two Windows resource imports to declared deterministic test fixtures, recording exact arguments and results. All original reset/fill/predicate/classification instructions remain intact. Bounded loop resumptions must preserve CPU/flags/stack and resume the same original instruction; no engine calls may be replaced. Reports must separate original entries/segments, external fixture calls, null returns and component-scan stops. Full successful remapping, one-megabyte component-stack allocation, cleanup and malformed-resource behavior remain explicit future work.
